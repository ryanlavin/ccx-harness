## Coverage Target

Target: **85 to 90 percent line and branch coverage on new code.** Not 100. 100 is bad engineering; you end up testing trivia and shipping slower.

What to cover (the 85 to 90):
- All business logic in new functions
- All explicit error paths and retries
- Every state transition and conditional branch
- Every acceptance criterion above maps to at least one test

What to skip on purpose (the 10 to 15):
- Trivial getters / setters / pass-through wrappers
- Framework boilerplate (Next.js route handler exports, React prop spreading, etc.)
- Code paths that exist only for type narrowing
- Third-party SDK glue with no project-specific logic on top
- {{PROJECT_SPECIFIC_SKIPS}}

If you can't hit 85 percent on a particular module without testing trivia, stop and surface that in the Operator Log; the user will decide whether to lower the target for that module or restructure the code.

## Iteration Policy

Codex, follow these rules while iterating:

1. Run the full test suite after each material change. Keep going while failure mode changes (no iteration cap).
2. If you see **3 identical failures in a row**, stop, flag the blocker in the Operator Log, and skip to the next scenario.
3. Push to the working branch as you iterate. Do not hold changes locally past one passing test.
4. After every meaningful step, append a one-line note to the Operator Log below with timestamp, status (PASS / FAIL / BLOCKED), and what you did.
5. When all acceptance criteria pass and all three test layers are green, write a final `DONE` line to the Operator Log and stop.
